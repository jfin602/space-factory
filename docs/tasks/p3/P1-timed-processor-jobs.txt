SCOPE AND STEPS

2. Start with the processor explicitly disabled and no active job. Add a small enabled state and one active job carrying identity, committed input, duration/progress, and completion status. Provide a production-step operation for the forthcoming shared driver and focused checks; do not add a Timer, _Process callback, coroutine, wall clock, or independently advancing job clock. P2 supplies authoritative solar availability; the job rule accepts that availability and never requires propellant to start.
3. A new job may start only when enabled, power is available, processor input contains at least I, and processor output has room for the complete O batch. A missing pipe or empty tank is not a start prohibition. Debit I once and create the corresponding job as one transition. Repeated enable requests or step calls cannot debit that same job again. Keep the committed material attributable to the job until its output commits.
4. Advance the active job only by eligible simulation quanta. An already-started job continues when uncommitted processor input reaches zero; missing input blocks the next job, not the work already paid for. Stop or unavailable power freezes job progress and retains its identity and material. Re-enabling resumes that same work without a refund, extra debit, restart, or instant completion. There is no cancellation/refund mechanic in this scope.
5. On completion, add O to the real processor output exactly once and retire that job exactly once. Recheck enabled state, sufficient power, and full-batch capacity at commitment. If any condition prevents commitment, retain the completed job and its accounted material until all conditions hold; never discard, partially publish, or repeatedly create its product. A pending completion prevents another job from taking input. A full output prevents a new input debit. Permit later eligible ticks to start subsequent jobs so processing is not restricted to one cycle per rendered frame.
6. Expose inspection of enabled state, active job/progress, and causal status from the same owner. Use the shared precedence: Off, No power, completed job blocked on output, active paid job Running, no-job Missing input, insufficient output room Blocked output, then eligible processing Running. P4 will present these values and add the actual nearby controls.
7. Add focused C# checks using the implemented owner and production operation.
