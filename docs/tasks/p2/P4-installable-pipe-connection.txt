SCOPE AND STEPS
1. Activate Install in P3's existing socket panel through its shared action dispatcher. Require the matching active panel opening and recheck Walking mode, target identity, current proximity, carried pipe stock, and uninstalled state when applying the action; a displayed hint or previously opened panel is not authorization to mutate later. Retain the panel's E/Esc close behavior, invalidation on range/mode change, and Piloting E exit. Do not add another E listener or let one press both close the panel and use the helm.
2. Make installation one synchronous transaction: consume exactly one carried pipe and establish the installed route once, or leave both inventory and connection unchanged. A missing part, distant/piloting attempt, or repeated installation must return the actual refusal reason. Reopening UI or switching modes must never award another part or install another route.
3. Bind that route to stable processor-output and tank endpoints in P1's authoritative state. Define a finite positive throughput and honor actual receiving capacity. The transfer operation accepts elapsed game time from a future authoritative caller; for a valid interval it moves no more than available source, free destination space, or rate times elapsed time. Debit and credit the same amount once. Disconnected routes, empty output, full tanks, or invalid/nonpositive/nonfinite intervals move nothing and cannot create negative/nonfinite inventory. Do not add a render callback or normal-play delivery scheduler in this phase.
4. Keep the installed tank-to-engine route tied to this same tank, with any exposed available reserve derived only from its actual stored quantity. It must not pool unrelated buffers or treat Installed as fuel. No engine consumption or applied thrust is added. The ordinary tank remains empty because no processor recipe exists yet.
5. Present the missing/installed segment and endpoints from real connection state. Retain P3's readable transaction result long enough to inspect, expose useful installed/missing-part feedback, and keep the gap and helm reachable. Update empty-supply feedback from the real tank/capability state without implying that connection alone enables flight. Do not animate material flow when no material moved.
6. Add focused C# checks through the existing smoke path for successful one-time installation, duplicate/missing-part rejection, and denied mode/range attempts through the actual action boundary. Exercise disconnected, rate-limited, source-limited, and capacity-limited transfers using a fresh isolated instance with a known processor-output quantity. Assert total output-plus-tank conservation, endpoint identity, repeat-call behavior, invalid intervals, and tank-only engine reserve. This isolated fixture is check setup, never a normal scenario seed/debug refill. Emit a distinct marker such as SPACE_FACTORY_M1_P2_CONNECTION_OK only after assertions pass and preserve existing smoke failures.
